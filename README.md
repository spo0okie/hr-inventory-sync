# SAPsync

Скрипты синхронизации кадровых данных между внешними кадровыми системами (SAP, 1С), базой инвентаризации и порталом Bitrix24, а также несколько сервисов самого портала.

Все скрипты запускаются из шелла (обычно по cron), а не через веб, и требуют запуска **из корня репозитория** — конфиг и библиотеки подключаются относительными путями.

## Состав репозитория

### Синхронизация

| Скрипт             | Направление        | Что синхронизирует           |
|--------------------|--------------------|------------------------------|
| `inventory-SAP.php`| SAP → инвентаризация | оргструктура и сотрудники  |
| `inventory-1C.php` | 1С → инвентаризация  | оргструктура и сотрудники  |
| `portal.php`       | SAP → Bitrix         | оргструктура, сотрудники, группы, фотографии |
| `absence.php`      | SAP → Bitrix         | отсутствия                 |
| `absenceC1.php`    | 1С → Bitrix          | отсутствия                 |

Скрипты `inventory-*.php` и `portal.php` не привязаны к конкретному источнику жёстко: класс хранилища выбирается по полю `src` дескриптора источника в конфиге (`sap` / `c1` / `sql`), а формат загрузки — по полю `ftype` (`json` / `xml` / `csv` / `sql`). Разделение на `-SAP` и `-1C` версии отражает не источник как таковой, а различия в обработке: `inventory-SAP.php` дополнительно раскладывает подразделения по юрлицам через `$inventoryOrgs`, пишет хеш СНИЛС и выполняет обратную запись контактов в SAP, а `inventory-1C.php` этого не делает и пишет в другую колонку дерева (`pup` вместо `hr_id`).

`portal.php` при этом безусловно обновляет кэш SAP (`system("$sapCache")`) до загрузки данных, поэтому с источником, отличным от SAP, его использовать без правок нельзя.

### Сервисы портала (не синхронизация)

| Скрипт              | Назначение                                                                 |
|---------------------|----------------------------------------------------------------------------|
| `absenceSubscr.php` | Обработчик сервиса «подписка на отсутствия коллег»: рассылает сотрудникам оповещения о приближающихся отсутствиях тех коллег, на которых они подписаны (поле `UF_ABSENCE_SUBSCR`). Данные берёт из портала, к SAP не обращается. |
| `bDayReminder.php`  | Напоминалка о днях рождения: раз в неделю отправляет в службу персонала список сотрудников, у которых день рождения сегодня или в ближайшие 6 дней. Данные берёт из портала. |

### Вспомогательное

| Файл             | Назначение                                                        |
|------------------|-------------------------------------------------------------------|
| `dupesCheck.sh`  | Выбирает из лога последней синхронизации (`/var/log/SAPsync.last`) предупреждения о дубликатах пользователей и сообщает, если список изменился. |
| `libs/`          | Классы хранилищ, см. [CLAUDE.md](CLAUDE.md) — раздел «Архитектура». |

## Запуск

```sh
php portal.php                 # оргструктура и пользователи
php portal.php photos          # то же плюс фотографии
php portal.php ivanov.i        # один пользователь по LOGIN в Bitrix, без прохода по оргструктуре
php portal.php ivanov.i photos # один пользователь вместе с фотографией
php inventory-SAP.php
php absence.php
php absenceSubscr.php
php bDayReminder.php
sh  dupesCheck.sh
```

## Конфигурация

Рабочий конфиг — `config.php` (в gitignore, содержит учётные данные). Шаблоны: `config.sample.php` и `config.php.yml`.

Пример описания источника данных для одного юрлица:

```php
$dataSrc_1c_org1=[  //описываем организацию 1
	'org_id'=>1,      //индекс организации в БД инвентаризации
	'org'=>[          //оргструктура организации
		'src'=>'c1',    //тип - выгрузка из 1C
		'ftype'=>'csv', //формат - CSV файл
		'path'=>'/tmp/sync_inventory/out_str2.csv',
	],
	'usr'=>[          //список сотрудников организации
		'src'=>'c1',    //тип - выгрузка из 1С
		'ftype'=>'csv', //формат - CSV файл
		'path'=>'/tmp/sync_inventory/out2.csv',
	],
	'abs'=>[          //отсутствия сотрудников организации
		'src'=>'c1',
		'ftype'=>'csv',
		'path'=>'/tmp/sync_inventory/out_nowork.csv',
	],
];
```

Какой источник использует какой скрипт:

- `inventory-SAP.php`, `inventory-1C.php` — перебирают `$inventory_import['sources']`, набор синхронизируемых полей задаётся в `$inventory_import['fields']`.
- `portal.php` — берёт единственный источник из переменной `$dataSrc_SAP`.
- `absence.php` — источник не использует, читает файл `$sapAbsenceFile` напрямую.
- `absenceC1.php` — перебирает `$inventory_import` и берёт из каждого элемента ветку `'abs'`.

## Предохранители

Синхронизация деактивирует в портале пользователей, отсутствующих в источнике, поэтому пустая или обрезанная выгрузка способна массово отключить портал. Для защиты от этого:

- `portal.php` прерывается, если из источника загрузилось менее 50 узлов оргструктуры или менее 250 пользователей;
- `absence.php` прерывается, если загружено менее 100 записей об отсутствиях;
- `$inventory_import['readonly_mode']` заставляет `inventory-*.php` печатать SQL вместо выполнения;
- свойство `$readOnly` у объекта хранилища отключает запись в Bitrix.

## Известные проблемы

Часть скриптов не запускается в текущем виде — подробности в [CLAUDE.md](CLAUDE.md), раздел «Устаревший код»:

- `absenceC1.php` подключает библиотеки по путям до реорганизации `libs/` и перебирает `$inventory_import` как плоский список, тогда как в текущем конфиге это словарь с ключами `sources` и `fields`;
- `portal.php` читает источник из переменной `$dataSrc_SAP`, которой нет ни в `config.sample.php`, ни в `config.php.yml`, а в рабочем конфиге источник назван иначе.
