# Расширения портала

Код, который живёт **на стороне Bitrix**, а не в синхронизации: структура папки повторяет `/local/` портала, установка — копированием.

```
portal/local/  ->  /home/bitrix/www/local/
```

Ванильные компоненты и ядро (`/bitrix/…`) не трогаются: всё лежит в `/local/`, который при обновлениях Bitrix не перезаписывается.

## Отсутствия в профиле сотрудника

Выводит текущие и запланированные отсутствия человека на странице его профиля. Данные — из графика отсутствий портала (инфоблок абсанс-календаря, тот самый, что наполняет `portal-absence.php`); ничего не пишет.

| Что | Где |
|---|---|
| компонент `sapsync:absence.user` | `local/components/sapsync/absence.user/` |
| гаджет «Отсутствия» | `local/gadgets/sapsync/absence/` |

### Прежде чем ставить

Страница профиля (`socialnetwork.user_profile`) собирается компонентом `bitrix:desktop` из гаджетов, и **штатный гаджет отсутствий там уже подключён**:

```php
$arDesktopParams["G_SONET_USER_ABSENCE_USER_ID"]   = $arResult["User"]["ID"];
$arDesktopParams["G_SONET_USER_ABSENCE_IBLOCK_ID"] = $arParams["CALENDAR_USER_IBLOCK_ID"];
```

Инфоблок отсутствий (ID 3) — это абсанс-календарь интранета, то есть штатный гаджет читает те же данные. Сначала проверьте, что показывает он: если в `CALENDAR_USER_IBLOCK_ID` на странице профиля стоит 3 и гаджет «Отсутствия» включён в раскладке, задача может быть уже решена без единой строки кода.

Свой гаджет нужен, когда штатный не устраивает: показывает не тот период, не выводит запланированные отпуска, не тот вид.

### Установка

1. Скопировать `portal/local/` в `/local/` портала.
2. На странице профиля нажать «Настроить» (доступно администратору) и добавить гаджет **«Отсутствия»**.
3. Сохранить раскладку по умолчанию — гаджет появится у всех сотрудников.

Правки шаблонов при этом не требуются вовсе.

Если гаджет не появился в списке доступных — портал старый и не сканирует `/local/gadgets/`. Тогда положите папку гаджета в `/bitrix/gadgets/sapsync/absence/` (своя папка вендора внутри `/bitrix/gadgets/` при обновлениях не затирается, затирается только `bitrix/`).

### Если раскладку менять нельзя

Компонент самодостаточен и вызывается откуда угодно одной строкой:

```php
$APPLICATION->IncludeComponent("sapsync:absence.user", "", array(
    "USER_ID"   => $arResult["User"]["ID"],
    "IBLOCK_ID" => 3,
    "COUNT"     => 5,
));
```

Вставлять её в шаблон профиля следует **не в `/bitrix/components/…`**, а в копию шаблона в `/local/templates/<шаблон сайта>/components/bitrix/socialnetwork.user_profile/.default/template.php` — тогда ядро остаётся нетронутым.

### Как гаджет узнаёт, чей профиль открыт

`bitrix:desktop` передаёт гаджетам параметры вида `G_<КОД>_USER_ID`, но в шаблоне профиля они перечислены поимённо — сторонний гаджет туда не попадёт без правки шаблона. Поэтому гаджет определяет пользователя сам: настройка гаджета → `user_id` в запросе → ID из адреса `/company/personal/user/<ID>/` → текущий пользователь.

Если в вашем портале адрес профиля устроен иначе, поправьте регулярное выражение в `local/gadgets/sapsync/absence/index.php` — это единственное место, где адрес разбирается.

### Параметры

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `USER_ID` | текущий пользователь | чей профиль |
| `IBLOCK_ID` | 3 | инфоблок отсутствий |
| `COUNT` | 10 (в гаджете 5) | сколько записей показывать |
| `SHOW_PAST_DAYS` | 0 | показывать и закончившиеся, столько дней назад |
| `CACHE_TIME` | 3600 | кэш; сбрасывается сам при правке инфоблока |

Оформление типов — в `templates/.default/style.css`, классы по коду типа (`--vacation`, `--vacation_plan`, `--assignment`, `--leavesick`…). Коды берутся из `XML_ID` вариантов свойства `ABSENCE_TYPE` и совпадают с типами отсутствия в ARMS, так что цвета не поедут при смене ID вариантов списка.
